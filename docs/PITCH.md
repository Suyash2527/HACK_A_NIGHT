# QuantumShield — five-slide pitch

Assumption: judging prioritizes innovation, impact, feasibility and a working demo; the only numerical claim below is a reproducible demo calculation, not a market statistic.

| Slide | On-screen copy | Visual / speaker cue |
|---|---|---|
| **1 · Problem: a tiny change, a large trust gap** | **1 byte in a 16 KB record = 0.0061% of the file. Enough to change its contents.** Investigators, labs and courts need to know who submitted evidence, whether it changed, and which original can be trusted. Records must remain defensible for decades. | One highlighted character in a fictional FIR. Footnote: `1 / 16,384 × 100 = 0.0061035%`; measured fixture size, not incident prevalence. Say “A file that opens successfully may still contain altered evidence.” |
| **2 · Solution: evidence with a verifiable history** | Encrypt every upload. Restrict every request by role and case. Sign and anchor evidence commitments. Detect altered chunks. Recover protected originals as new versions. | Three compact panels: **Protect → Verify → Recover**. Explain that append-only versions preserve both the incident and the correction. No claim that tampering is impossible. |
| **3 · Live demo: change one byte; expose the difference** | Police uploads → lab denied on an unassigned case → prosecutor verifies → insider changes one byte → scan red, chunk located, original restored → optional cited assistant answer. | Run DEMO_SCRIPT's five steps; the insider scene is the centerpiece. Show last accessors as context, not attribution. Amber means waiting, green requires completed verification; label recordings/mock scenes. |
| **4 · Architecture: layered trust, visible boundaries** | Next.js on **EC2 + CloudFront**. **Cognito + API policy + RDS PostgreSQL RLS** enforce identity/case access. **AES-256-GCM + ML-KEM-768**, protected key material via **KMS**. Ciphertext in **S3 + SSE-KMS + versioning + Object Lock**. **ML-DSA-65 + chunk/batch Merkle trees → Polygon Amoy**. **Bedrock + pgvector**: optional authorized retrieval. | Layout as three lanes: identity/access; encrypted evidence/recovery; commitments/audit. Add EventBridge scans and CloudTrail AWS events only if wired, otherwise mark planned. Explicit caption: “PQ signatures verified off-chain by our backend; Polygon stores hashes and verifier attestation, not on-chain PQ verification.” Hash-chained signed app audit detects modification; it is distinct from CloudTrail. |
| **5 · Impact & next steps: make evidence challenges answerable** | For officers: controlled submission. For labs: case-scoped collaboration. For prosecutors and courts: inspectable integrity and custody. Next: independent security review, retention/key-recovery policy, institutional pilot, operational resilience. | Demo acceptance targets, not claimed field results: detect 1/1 injected byte-change; identify the correct 4 KB chunk; deny and record unassigned access; retain the damaged history while restoring content. Measure scan latency and recovery time during rehearsal before quoting them. |

Architecture speaking note: ML-KEM protects document-key wrapping and ML-DSA signs commitments; these do not make Polygon consensus or its transaction signatures quantum-safe. Backend verifier integrity and protected signing/decryption keys remain trust dependencies. Application audit is tamper-evident, not invulnerable to a fully compromised signer. Object Lock retains versions for their configured retention, not forever.

Next-step order: validate independent verification and access controls → production KMS/key custody and rotation → backup/retention/recovery drills → institutional workflow pilot → scale scans and anchor reliability → add Bedrock assistance after the evidence path is reliable. Full post-quantum protection of the anchoring network remains outside this prototype.

Closing line: **“QuantumShield makes altered evidence visible—and keeps a trustworthy original within reach.”**
